# zephyr - Subscription Entitlement

`SubscriptionService` owns the lifecycle of a SaaS subscription and answers
whether a subscription currently grants access. The service is in-memory,
single-process, and takes an injected clock so expiry behaviour is deterministic
in tests.

## Domain model

A `Subscription` has:

- `sub_id` - generated by the service (`S1`, `S2`, ...)
- `user_id` - the account that owns it
- `status` - one of `TRIAL`, `ACTIVE`, `SUSPENDED`, `CANCELLED`, `EXPIRED`
- `expires_at` - the trial expiry instant, or `None` when there is no expiry

`TRIAL` is free access with a time limit. `ACTIVE` is paid access. `SUSPENDED`
is paid access that has been paused. `CANCELLED` and `EXPIRED` are terminal and
distinct: cancellation is a user action, expiry is the passage of time.

## Lifecycle

| From | Event | To |
| --- | --- | --- |
| `TRIAL` | `activate` | `ACTIVE` |
| `TRIAL` | `cancel` | `CANCELLED` |
| `TRIAL` | trial TTL reached | `EXPIRED` |
| `ACTIVE` | `suspend` | `SUSPENDED` |
| `ACTIVE` | `cancel` | `CANCELLED` |
| `SUSPENDED` | `resume` | `ACTIVE` |
| `SUSPENDED` | `cancel` | `CANCELLED` |

Nothing leaves `CANCELLED` or `EXPIRED`.

## Public API

### `start_trial(user_id) -> Subscription`

Creates a `TRIAL` subscription with `expires_at = now + trial_ttl_seconds`.

### `activate(sub_id) -> Subscription`

Turns an unexpired trial into paid access and clears the trial expiry.

### `suspend(sub_id) -> Subscription`

Pauses an active subscription.

### `resume(sub_id) -> Subscription`

Returns a suspended subscription to active.

### `cancel(sub_id) -> Subscription`

Cancels a live subscription.

### `is_entitled(sub_id) -> bool`

Reports whether the subscription currently grants access.

An unknown `sub_id` raises `ValueError`.

## Repository map

```text
python/subscriptions.py   SubscriptionService and Subscription
cpp/subscriptions.hpp     header-only equivalent
java/Subscriptions.java   equivalent

```

The same behaviour is implemented in all three languages. Pick one.

## Scope and time

In scope: find where the implementation deviates from this specification, write
a test that proves each deviation, fix the narrowest layer, and keep existing
correct behaviour working.

Out of scope: redesigning the component, changing the public API, or adding
features the specification does not describe.

Time budget: about 35 minutes.

This pack ships no tests. Read the spec, ask the interviewer about the edge
cases, then write your own tests.
